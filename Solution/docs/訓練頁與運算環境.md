# 訓練頁與運算環境

Modal 詳細設定與登入步驟見 [Modal 微調設定與操作](Modal微調設定與操作.md)。GPU、CPU、RAM 與 timeout 現由 `Solution/config/modal_finetune.json` 決定，建立工作時保存設定快照。

從側欄「模型訓練」或評分頁的「訓練模型」進入。選擇訓練方式、運算環境、資料來源（專案 history 或自行選取 JSONL）及保存根目錄，確認 history 來源後開始。每次工作保存獨立的設定、資料／程式快照、事件、模型與比較報告；不自動取代預設模型。

## 三種環境

| 環境 | 支援方式 | 準備 |
|---|---|---|
| CPU | BGE 聯合微調比較、固定 BGE、TF-IDF | 安裝對應 requirements，準備固定 BGE 本機資產 |
| 本機 GPU | BGE 聯合微調比較 | NVIDIA CUDA 驅動與 CUDA 版 PyTorch；不支援時明確失敗，不自動轉 CPU |
| Modal | BGE 聯合微調比較，T4 GPU | UI worker 的 Python 安裝 `Solution/requirements-modal.txt`，以 `python -m modal setup` 登入 |

安裝模型依賴：`python -m pip install -r Solution/requirements-embedding.txt`。CPU／CUDA PyTorch 的 wheel 應依執行設備選擇；可參照 [PyTorch 官方安裝頁](https://pytorch.org/get-started/locally/)。此頁不會自動安裝套件、登入或切換執行環境。

Linux／WSL worker 使用專案 `.venv/bin/python`。Windows 優先使用 `.venv/Scripts/python.exe`，其次使用 `helper_tool/reports/training-runtime/Scripts/python.exe`；兩者皆不存在時使用啟動 UI 的 Python，因此啟動 UI 的環境需要有訓練依賴。Windows 可用 `python -X utf8 helper_tool/ui_server.py --no-browser` 啟動，或雙擊 `helper_tool/啟動訓練UI.cmd`。啟動器優先使用本機已建立的 `helper_tool/reports/training-runtime` 隔離環境，其次使用 Windows `.venv`，最後使用系統 Python；不自行安裝依賴。

GPU 選項會讓 encoder、分類頭、輸入、標籤與 loss 權重移到 CUDA，保留 float32 與既有 loss、資料切分及選 epoch 規則。LR／SVC 對照的 sklearn 擬合仍使用 CPU；保存的模型可在 CPU 載入。GPU 訓練不保證與 CPU 逐位元相同，也不保證分數改善。訓練沒有 2 GB 限制，部署後仍須另外驗證推論資源。

## Modal 資料與模型傳輸

本次功能依使用者明確授權，允許把當次選取的 history 傳到 Modal 訓練；每次工作仍記錄 `cloud_upload_confirmed`，UI 需勾選本次上傳與 GPU 費用確認。未勾選時 API 拒絕啟動。這不是上傳整個專案 data 的許可，其他原始資料／逐筆紀錄仍遵守專案只留本機的規範。

Modal image 僅包含本次程式快照、公共設備／錯誤碼表、設定及固定 BGE 資產；history 作為單次函式輸入傳送，不掛載專案 data、既有 reports、`.venv`、Git 或憑證目錄。不設永久資料 Volume。遠端在暫存目錄完成比較，串流回傳進度事件與分塊模型封裝；下載完成後核對 SHA-256、檢查封裝路徑，並將模型路徑改為本機工作資料夾。

Modal 平台仍可能保留執行紀錄與檔案快取；未配置 Volume 不代表第三方立即抹除資料。首次 image 建置與模型傳送需額外時間。登入資料由 Modal SDK 管理，不由表單輸入或寫入訓練設定；GPU 及相關平台服務可能計費。連線／下載失敗會標記失敗，保留本機紀錄，不自動重試付費訓練。本機 worker 必須持續執行，UI 服務可重新啟動；主機重開或 worker 結束後不保證遠端工作續接。

實作依據：[Modal Functions](https://modal.com/docs/guide/functions)、[Image 本機檔案掛載](https://modal.com/docs/guide/images)、[GPU](https://modal.com/docs/guide/gpu)。

## TF-IDF／凍結 BGE 的 LR／SVC 訓練參數

選「既有 TF-IDF＋LR／SVC」或「既有凍結 BGE＋LR／SVC」時，表單會出現「LR／SVC 訓練參數」。預設值就是原本寫死的配方，不改設定時結果和以前一樣；按「恢復預設值」可以還原。設定會套用到全部四個候選（原文／遮罩設備名稱 × LR／SVC），使用的參數保存在訓練紀錄的 `config.json`、`models/comparison.json` 與模型 metadata。

| 參數 | 預設 | 適用 | 說明 |
|---|---|---|---|
| 正則化強度 C | 1.0 | 兩者 | 越小越保守、越不容易過擬合；越大越貼合訓練資料。範圍 0.001～1000 |
| 類別權重 | balanced | 兩者 | 依各類數量自動平衡；也可選不加權 |
| 資訊不足判斷 C | 1.0 | 兩者 | 判斷 category=null 的另一個 LR 分類器 |
| LR／SVC 最大迭代次數 | 2000／5000 | 兩者 | 出現未收斂警告時再調高 |
| 切字方式 | char | TF-IDF | `char` 連續字元；`char_wb` 只在詞內切 |
| n-gram 長度 | 2～4 | TF-IDF | 取幾個連續字元當特徵，範圍 1～6 |
| min_df | 1 | TF-IDF | 出現在少於這麼多張工單的片段會被丟掉 |
| 特徵數上限 | 0（不限） | TF-IDF | 否則至少 100 |
| sublinear TF | 開 | TF-IDF | 同一片段重複出現時以 log 降低權重 |

凍結 BGE 的 encoder 不訓練，所以只有分類頭參數。命令列也能用：`.venv/bin/python Solution/train.py --settings-json '{"c": 0.5, "ngram_max": 3}'`（`train_embedding.py` 相同，只接受分類頭欄位）。

## 進度與指標

頁面每 2.5 秒讀取持久化工作狀態。BGE 聯合微調的進度依真實 batch 完成數更新，同時顯示方法、epoch 與 batch。整體百分比依預先定義的階段權重估計，並非剩餘時間預測；雲端建置、特徵準備、驗證、模型保存與下載顯示階段文字。sklearn 四候選訓練使用不定長度進度條，完成後才顯示 100%，不偽造 batch 進度。提早停止後會進入下一階段。

結果延續各模型原本的 metric：文字分類 macro-F1、含 unknown 的六類 macro-F1（選 epoch）、unknown recall，以及共用管線的 category macro-F1、設備正確率、urgency macro-F1、duplicate F1 與加權總分。文字分類與共用管線的分類分數範圍不同，分欄顯示。每個 epoch 顯示 train loss、訓練／驗證六類 F1 與驗證分類 F1；沒有事後換選型指標。結果完成一組便更新比較表，成功後可「帶入預測」。

驗證段來自 history 的時間與近似模板切分，兼用於選 epoch，屬於選型驗證，不能當作獨立測試成績。聯合微調保存最佳 train-only checkpoint；既有四候選流程保存完整 history 重訓資產，頁面會區別其範圍。dev 不提供訓練選項，檔名限制仍不能證明內容未混入保留集。沿用 A 規則曾觀察 dev 的來源限制仍適用。

## API

`POST /api/training` 在既有 payload 加入 `backend: "cpu" | "gpu" | "modal"`，未填視為 CPU。Modal 另外要求 `cloud_upload_confirmed: true`，與 `history_only: true` 分開。GPU／Modal 目前只接受 `kind: "bge-finetune"`。

`GET /api/training` 與 `GET /api/training?id=...` 回傳持久化的 `progress`、逐 epoch 事件與 `comparison`。batch 全紀錄留在本機 `events.jsonl`，API 不以大量 batch 事件擠掉 epoch 指標。Linux 使用繼承檔案鎖；Windows 使用啟動鎖與存活 worker 檢查，同一專案只允許一個工作。
