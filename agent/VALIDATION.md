| 檢查 | 結果 | 外部計時 |
|---|---|---|
| 程式／資料契約測試 | 25 項通過，包含 Windows 子程序生命週期 | 約 0.1 秒；不是 LLM 準確率 |
| 人工合成問答 suite，固定 v2 | 11/12 | 最短 9.323 秒、中位數 10.209 秒、最長 12.029 秒 |
| history 問答 suite，固定 v2 | 12/12 | 最短 9.604 秒、中位數 10.513 秒、最長 11.940 秒 |
| 12 張合成工單的巡檢契約 smoke | 通過：輸出 10 張唯一工單，引用均可對回原文 | 13.383 秒 |
| 正式預設 tickets 路徑的總數查詢 smoke | 回答 2,000、20 個 evidence、exit 0 | 9.518 秒 |

兩套問答各含 6 題相同的公開對照表問題，不能視為 24 題互相獨立的測試。history 題目的預期答案以原始四欄獨立計算，不讀標籤。全部測試都是開發資料上的結果，不代表隱藏題或所有自然語言問題的成績。

每題均重新啟動程序、載入與關閉模型；沒有清除 OS 檔案快取。問答中模型程序與 CLI 各自峰值工作集相加的最大值約 **2.267 GiB**，是兩程序峰值 RSS 的上界，不含 OS 或其他程序，也不是 commit memory／模型檔案大小。**尚未在 8 GB 硬限制環境下驗證**，不能把低於 8 GB 的觀測值當作已完成記憶體限制演練。

## 已知錯誤與開發觀察

- 合成 `reporter-count` 題仍失敗：模型把完整回報人名稱縮成單字，工具精確比對後得到 0。工具本身的完整姓名計數有契約測試，但自然語言到參數的正確性仍有限制。沒有針對這個姓名增加特例。
- 初始模型容易混用位置、設備識別與 single／critical 旗標，設備查詢拆為不同用途工具後改善。文字篩選也曾漏條件，現在明列參數語意、示例並回傳 applied_filters 供模型核對。
- 巡檢曾因模型把多段症狀改寫成非逐字引句而拒絕輸出；一次模型修正仍不足，最終改由程式從選中原文擷取證據，模型負責選單、排序及優先程度。
- 巡檢僅驗證選單／引文契約；是否真正選出全資料最急的工單仍需人審。安全詞與時間的候選篩選可能漏掉其他措辭的急件。
- 尚不支援一般自由文字摘要、所有語意分類、錯字／代稱消解、跨 observation 的新答案組合。工具字面匹配不能冒充語意全集。
